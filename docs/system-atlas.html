03 · How it stays safe

Design patterns

Models read, rules decide. Each pattern below is in the code, at the path shown.

Rules first, model fills gaps

The parser and regex rules answer first. A model only fills fields the rules left empty, and a disagreement becomes a question, never a silent swap.

engine/request_job.py

Grounded extraction

Every value a model returns must be an exact slice of the input, or it is dropped and counted: 115 attempts in 300 requests on Ministral 8B, none got through.

engine/ground.py

Two identifiers, calibrated match

Name and birth date, scored by a Fellegi–Sunter record-linkage model. A patient is picked only with a clear margin; otherwise the bot asks back.

core/fs_matcher.py · engine/patients.py

Ports and adapters

Delivery channels, the patient directory and the model backends are interfaces. Mailpit, the SMS page, FTAPI SubmitBox, HAPI, vLLM or llama.cpp plug in behind them.

app/delivery/base.py · engine/backends/

Capability link

A 256-bit random token per request. Only its SHA-256 is stored; it expires after 72 h, works once and locks after 5 failed identity checks.

app/tokens.py

Need-to-know reveal

The link page shows one neutral sentence. Patient and document type appear only after the eID name matches the person Dr. Hofer named.

app/main.py · app/identity/policy.py

Transactional outbox

Chat messages and SMS are written as rows first and the bot drains them, so a Matrix outage never loses a notice.

app/notify.py

Hash-chained audit log

Append-only. Each row stores the previous row's hash, so editing or deleting any entry breaks the chain from that point.

app/audit.py

Human read-back

A photo or scan is never filed directly. The sender confirms the values on screen, like a critical value read back on the phone.

engine/document_job.py

Graceful degradation

GPU model, then CPU model, then rules only. The engine always answers; without models it asks back more often.

engine/config.py

One command handler

Typed commands, the CLI, voice notes and chat buttons all go through one handler, so permissions are checked in one place.

app/commands.py · app/reactions.py

Living card

One chat message per request, edited in place as the status changes. A short ping only when Dr. Hofer has to act.

app/status_message.py

05 · What is stored, where

Data

The app keeps its own records in SQLite and files results as FHIR R4 on HAPI. Patient data never travels in an email or SMS.

App database · SQLite · 9 tables

Blue lines are foreign keys to requests.id. Arrows in a row (→) are references by value: to the audit log, the chat, or a FHIR resource on HAPI.

FHIR R4 resources filed for one lab answer

Filed as one transaction Bundle, only after the core decides "file" and HAPI's $validate reports no errors. A rehab report files a DocumentReference with its author instead of Observations.
