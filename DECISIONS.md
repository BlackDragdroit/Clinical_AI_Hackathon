## Engine (AI) — Thu night
- One engine service (`engine/`, FastAPI `engine.api:app`) with two jobs: request (typed/spoken DE+EN → checked request) and document (Markdown/PDF/scan/photo → scenario-shaped Markdown + checks). The app calls it over HTTP when `ENGINE_URL` is set, in-process otherwise (dev, tests). — AI
- Grounding rule: every string the engine returns is a slice of its input (`engine/ground.py`); model values that are not in the text are dropped and counted (`dropped_ungrounded`). LOINC codes are never generated by a model. — AI
- Rules run on every request (CPU, ~1 ms) and cross-check the model; a disagreement on the contact blocks the field (asks back) instead of guessing. Model unreachable → rules only. — AI
- Patient lookup needs two identifiers (name + birth date) or an explicit `Patient/<id>`; the core's Fellegi–Sunter matcher ranks FHIR candidates; `unique` needs `file` and a ≥6-bit margin over the runner-up, otherwise the bot asks. — AI
- Markdown answers: core parser first; the model only reads documents the parser cannot. PDFs with a text layer take the same exact path. Scans/photos (OCR) are never filed straight away: the sender confirms a read-back screen; values the VLM and Tesseract read differently are highlighted. — AI
- Answer checks (deterministic, never block, never change a value): completeness vs. the requested panel, sample age vs. request date (lab > 14 days flagged), unit/plausibility per LOINC, document type vs. request. Shown in Dr. Hofer's message on file/review only, never on a reject. — AI
- Voice notes are processed in memory; only SHA-256 + model + timings go to the audit log (`request_parsed`). — AI
- core/fhir_build.py UCUM fix: `g/l` was mapped to `10*9/L`; now `G/l` → `10*9/L` (Giga, Austrian cell counts) and `g/l` → `g/L`. — AI
- Local venv lives outside the repo when the checkout path is long (`UV_PROJECT_ENVIRONMENT`), because Windows cannot load some native modules from very long paths. — AI
- Added `tzdata`: zoneinfo has no time zones on Windows without it. — AI
- **VERIFY** model ids and vLLM support on the A5000: `numind/NuExtract3` (template via `chat_template_kwargs`), `Qwen/Qwen3-ASR-1.7B` (`/v1/audio/transcriptions` passes `prompt` as context?), `PaddlePaddle/PaddleOCR-VL-1.6` (prompt format for full pages). Fallback text model: `Qwen/Qwen3.5-4B` with `ENGINE_LLM_MODE=json_schema`.
- Model picks (research Thu night, 3 per task): speech Qwen3-ASR-1.7B (DE WER 3.97 / EN 5.40, Open ASR Leaderboard 2026-10-28; language detection; vocabulary prompt) vs. Whisper large-v3 (baseline) vs. Parakeet TDT 0.6B v3 ONNX (CPU). Text→JSON NuExtract3 4B (Apache-2.0, extraction-tuned, verbatim-string type) vs. Qwen3.5-9B w4a16 vs. rules. OCR PaddleOCR-VL-1.6 (0.9B, best Real5 phone-photo score 93.19, German MDPBench 81.2 on v1.5) vs. dots.mocr 3B vs. Tesseract. All open weights, commercial-friendly licences (Parakeet CC-BY-4.0 needs attribution). Vendor-reported numbers; A5000 speeds unmeasured until the box is up. — AI
- GPU layout: three vLLM servers on one A5000 with fixed memory shares (0.42 text, 0.22 speech, 0.18 OCR); engine is a CPU container with Tesseract. Docker on the VM, no Kubernetes (decided Thu night). — AI
- Test sets: dev (600, templates) is for tuning only; the held-out set (300) was written by a separate model run that never saw the engine code or templates. Rules v1 were frozen on it (69.7 % fully correct); every later change is labelled v2 in eval/RESULTS.md because it was made after seeing that set. Next unseen set: the team's own requests (eval/data/requests_human.jsonl). — AI
- Request job v2: rules first, the model only fills gaps; on a disagreement the rules' value stays and the model's reading is shown as a flag. Reason: v1 (model wins) raised silent errors to 26 % with Qwen3-1.7B; v2 keeps them at the rules' 1.7 % and lifts fully-correct requests to 81.7 %. Same principle as the document job (exact parser first). — AI
- "Silent error" = the card is ready, a required field is wrong and nothing is flagged. Wrong-but-flagged is reported separately. — AI
- Contacts that come from a voice message are always flagged on the card ("Zeichen für Zeichen prüfen"): CPU speech-to-text produced one wrong phone number marked ready (eval/VOICE.md). — AI
- NuExtract3 runs in its template mode (verbatim strings); plain JSON-schema mode rewrites dates to ISO, which grounding then drops. Verified on llama.cpp b11985 (CPU, Q4_K_M); vLLM still to verify. — AI
- Mistral (EU, Apache-2.0) is measured, not assumed: Ministral 3 3B on CPU now, Ministral 3 8B and Voxtral Mini on the GPU via env switches. Data sovereignty comes from self-hosting, not from the model's origin; if Mistral is within the CI of the best model we ship Mistral for the EU story. — AI
- Real reference data, no patients (eval/REAL_DATA.md): ELGA_Laborparameter (7,929 parameters, German names, LOINC 2.83), Statistik Austria first names (CC BY 4.0), GraSCCo synthetic letters (CC BY 4.0). ELGA's preferred LOINC codes differ from our seed for some tests (Leukozyten 26464-8, Erythrozyten 26453-1, Hämatokrit 20570-8); to be folded into the lexicon. — AI
- Local CPU models (llama.cpp b11985, Q4_K_M GGUF: Qwen3-1.7B, NuExtract3, Ministral-3-3B) live in ~/.cache/befundbruecke, outside the repo; `make cpu-llm MODEL=…`. — AI
- Identity binding name rule (`policy.names_match`): titles, case, umlaut spelling ignored, hyphen = space; the eID family name must be exactly the last tokens Dr. Hofer typed (no missing or extra family part); every given name she typed must be on the eID in order, extra eID given names are allowed; a family name alone never matches. — MedEng
- No possession-only identity path (link without eID): it can't catch a forwarded link (M2). Outside people without ID Austria log in with their national EU eID via eIDAS; people with no eID at all can't answer, and the README says so. — MedEng
- `/audit` is a standalone template with its own styles (`_audit_style.html`), not an extension of `base.html`: the portal layout is a 34rem phone column, and the audit page is a wide staff screen. Colours: navy chrome, iris violet accent/focus, green = filed, amber = review, red = identity failed, orange = misdelivery, always with an icon and a word as well. — MedEng
- Audit page wording is built when the page renders (`audit.describe`), from the stored event codes and details. The log itself stays as written (German details, M1/M2/M3 codes), so changing the wording never touches the hash chain. — MedEng
- A broken chain is reported by the first failing row (`first_broken`), using the same rule as `verify_chain` (each row checked against the stored previous hash): an edited row flags itself, and a deleted row flags the row after it. — MedEng
- `/audit/apple` is a second look at the same audit page (Apple HIG: grouped sections, semantic icon tiles, segmented language control, disclosure triangles), built from the same `audit.view()` and i18n keys; `/audit` renders unchanged apart from a "Design: Standard / Apple" link, so the team can compare both and keep one. Secondary text is darker than Apple's 60 % grey so small text meets WCAG AA. — MedEng
- `/audit/apple` is now a formal audit record (document header with metadata, findings stated in words, plain hairline tables, a ledger timeline, navy accent, status only as dark text plus a 3px rule on failed/misdelivered entries) so the jury reads it as a clinic compliance record, not a consumer app; the light/dark/system switch (`app/theme.py`) was dropped and both audit pages are light only; the design switch moved to the footer. — MedEng
- One DE/EN catalogue for everyone: MedEng's `app/i18n.py`; the portal texts live there as `portal.*` / `doc.*` keys. Pages pick the language from `?lang=` then the `lang` cookie, else German. Accept-Language is not used, so the first page always shows the agreed German sentence, on any browser. — SWE 2 (MedEng to confirm)
- UI: one design system for every screen (`app/templates/_design.html`): light and clinical, cool ground, white paper, navy ink, one accent (clinic blue #1f5f8b) for links, focus and "in progress"; green only for filed, amber for review, red for problems, always with a word. Drawn SVG icons and a bridge mark instead of emoji in the UI (chat messages keep their emoji). The dashboard answers "what needs me?" first (Braucht Sie / Unterwegs / Abgelegt) and draws each request as a bridge of five stations; motion only on change. Audit pages keep their markup and map their variables onto the shared tokens. — AI
- OCR for scans and phone photos runs on the team GPU's Ministral 3 8B (the text model; no second model fits in the ~3 GB left): photo -> Markdown in ~5 s, the sender confirms every value on the read-back screen, then the core files it. Tesseract (second reader) is not installed, so no value is marked as agreed. The engine strips a general model's 'Sure, here is ...' wrapper and keeps the title line as the '# ' heading the parser takes the lab's name from. — AI
